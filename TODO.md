- [x] **Привязка Bizon-отчёта к вебинару.** Матчинг по дате или ID — связать отчёт с уже существующим Webinar в системе. Обогатить данные вебинара метриками из Bizon.
- [x] **Детальная статистика просмотра.** На основе Bizon CSV: график удержания (retention curve) — в какой момент люди уходят. Средний % досмотра. Пиковая аудитория. Это ключевые данные для оптимизации вебинара.

- [ ] **Корреляция досмотра и оплат.** Связать % досмотра каждого зрителя (из Bizon) с его действиями (заказал/оплатил). Ответить на вопрос: «С какого момента люди начинают покупать? До какой минуты нужно удержать, чтобы сконвертить?»

## Приоритет 3 — Точность аналитики

- [x] **Дедупликация контактов.** Периодический job, который находит контакты с одинаковым email или phone, но разным gc_user_id, и объединяет их. Без этого один человек может считаться дважды в воронке.
- [x] **Валидация входящих данных.** Обязательно хотя бы один идентификатор (gc_user_id / email / phone) в каждом webhook. Сейчас можно отправить payload без единого идентификатора — контакт создастся «пустым».
- [x] **Повторные регистрации.** Человек может зарегистрироваться на один вебинар через разные воронки. Нужна логика: считать первую регистрацию как основную, остальные помечать `is_duplicate`. В воронке считать только уникальных.
- [x] **Время присутствия на вебинаре.** Добавить поле `duration_minutes` в Attendance. GetCourse может передавать сколько минут человек был на вебинаре. Это позволит отличать «зашёл на 2 минуты» от «досмотрел до конца» и считать качественную доходимость.
- [ ] **Этапы воронки: детализация «после вебинара».** Сейчас воронка: регистрация → присутствие → заказ → оплата. Добавить промежуточные шаги: «открыл оффер» (отдельный webhook или событие), «оставил заявку», «начал оплату». Чем больше шагов — тем точнее видно, где теряются люди. _(v0.3)_
- [ ] **Когортный анализ.** Группировка пользователей по дате первой регистрации (когорта). Позволяет видеть, как ведят себя люди из разных потоков: какой процент из когорты марта оплатил в течение 7 / 14 / 30 дней. _(v0.3)_
- [ ] **Атрибуция: мультитач.** Сейчас атрибуция привязывает заказ к последнему посещённому вебинару. Добавить учёт всех касаний: первый источник (first touch), последний источник (last touch), все промежуточные. Это критично для понимания, какой вебинар реально продаёт. _(v0.3)_
- [x] **Скорость конверсии (time-to-action).** Считать и показывать: среднее время от регистрации до присутствия, от присутствия до заказа, от заказа до оплаты. Помогает понять, где люди «зависают» и нужен дожим.
- [x] **Отслеживание «мёртвых» лидов.** Люди, которые зарегистрировались, но ни разу не пришли на вебинар за последние N дней. Отдельный список для ретаргетинга или email-рассылки.
- [x] **Аномалии и алерты.** Автоматическое обнаружение: резкое падение доходимости (< порога), нулевые оплаты за день при наличии заказов, всплеск регистраций из одного источника (возможный фрод). Уведомление в Telegram или на дашборде.
